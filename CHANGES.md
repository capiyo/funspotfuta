# Changes — AdSense content and crawl readiness

Branch: `seo-app-at-root`

## Discovery

- The Vite web app builds a separate React SSR entry at `apps/web/src/entry-server.tsx`; Netlify's SSR handler is generated by `apps/web/scripts/generate-crawl-files.mjs`.
- The root request renders the authenticated workspace through `RootNavigator`; the public document renderer was `apps/web/src/screens/PublicDocument.tsx`.
- Fixture cards received fabricated comments from `MOCK_COMMENTORS` / `MOCK_COMMENTS` in `ChatsScreen.tsx`; the “Quick guide” was a separate static `QuickGuidePostcard` component in the same file.
- Channel and weekly leaderboard rows are service-backed; the frontend maps server `season_points`, `correct_votes`, `total_votes` and weekly `weekly_points`. The frontend does not define a universal correct-prediction point award formula.

## Implemented

- Removed generated fixture-comment fallback; known stock comment strings are rejected. Known demo accounts `guest_john` and `mary_ochieng` are filtered from channel, season and weekly leaderboard data.
- Public SSR now prefetches fixture data only; channel members and user-generated feed posts are not included in crawlable homepage HTML.
- Added a 166-word homepage editorial introduction, links to the first three guides, and a public footer on homepage loading and loaded states.
- Added canonical SSR pages at `/about`, `/contact`, `/privacy`, `/terms`, `/ads-disclosure`, `/insights` and six evergreen articles with Article JSON-LD and cross-links.
- Added a live-fixture preview data panel that uses an actual live fixture when the feed provides one and otherwise states that no live fixture is available.
- Centralized the public email in `apps/web/src/config/contact-email.mjs`. Post reports use a visible mailto action; moderation instructions are included in the public contact and terms pages.
- Feed media-only posts are withheld during SSR unless they contain at least 20 alphanumeric text characters; they become available after hydration. Video playback is now user-initiated rather than automatic.
- Crawl generation now writes clean route HTML, robots.txt and a sitemap with lastmod values. It verifies editorial length, one H1, canonical metadata, footer links, forbidden placeholder strings and the unchanged ads.txt record.
- Private app routes receive `noindex,follow`; the homepage, policies and editorial pages remain indexable.

## Verification status

- Source checks: article text is above 900 words for all six articles; homepage intro is 166 words; the six required placeholder strings are blocked from rendering, and all known stock lines are filtered from fixture comments.
- Build, local HTTP fetches, production HTTP checks and deployment were **not run** in this GitHub-only environment. The build-time crawl verifier has been added but still needs to execute in the project's Windows/Git Bash environment.
